# 本地大模型指挥官（可选）

这个目录放「让 AI 用大模型指挥」所需的本地资源。**整个目录不入库**
（模型 1.1GB、运行时 25MB），所以从仓库克隆下来时它是空的。

游戏默认不启用这一功能：设置 → AI 指挥官 → 大模型 才会加载。

## 需要两样东西

| 用途 | 放到 | 大小 |
| --- | --- | --- |
| 模型权重（GGUF） | `ai/*.gguf` | 约 1.1GB |
| 推理运行时（llama.cpp） | `ai/runtime/llama/llama-server.exe` | 约 25MB |

## 一键准备

```bash
python tools/get_llm_runtime.py          # 下载并解压 llama.cpp（约 25MB）
python tools/get_llm_runtime.py --check  # 检查模型与运行时是否就位
```

运行时从 llama.cpp 的官方发布包取，脚本会依次尝试直连与两个镜像。
**模型需要自己放**：把 `LFM3-1.7B` 的 GGUF 文件直接放在本目录下
（文件名任意，`lfm*` 前缀优先）。

## 为什么是 llama.cpp 而不是 llama-cpp-python

LFM3 是新架构，PyPI 上能直接装到的 `llama-cpp-python` 轮子（0.2.x）
带的是 2024 年的 llama.cpp，不认识 `lfm3` 这个 arch；从源码编译又需要
MSVC 工具链。官方发布的 Windows CPU 包解压即用，对玩家最省事。

## 它到底怎么用这个模型

模型不直接操作部队，只决定**每回合的作战决心**：主攻哪个目标点、
什么姿态（强攻/均衡/固守/游走）、优先打哪类目标、要不要分兵佯动。
具体行军、射击、电子战仍由规则 AI 执行——见 `core/llm_commander.py`
开头的说明。

这样做的原因是 1.7B 的模型没法可靠地输出带约束的动作串，但它对
「该往哪使劲」这类判断题给得出有意义的答案；而规则层本来就把
「怎么打」做得更好。
